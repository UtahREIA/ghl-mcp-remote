GHL Attribution Report Tool

Development Summary — MCP Server Extension for GoHighLevel

Project: ghl-mcp-remote Date: May 6, 2026 Prepared by: David Igberi

🎯 Objective

The goal was to determine whether Claude, via the existing GHL MCP remote server, could access GoHighLevel attribution report data and session events — and if not, to build that capability directly into the server.

The end result is a new MCP tool — ghl_get_attribution_report — that aggregates contact-level attribution data across the entire GHL database without requiring a paid reporting.readonly API scope.

📋 Background

The GHL MCP remote server (api/mcp.js) exposes GoHighLevel data to Claude via the Model Context Protocol. Before this work, the server had 48 tools covering contacts, conversations, calendars, funnels, workflows, social media, products, and more — but no attribution or session tracking tools.

What GHL Offers for Attribution

Data Source Where It Lives Requires Reporting Scope?
Contact-level attribution attributionSource + lastAttributionSource on each contact No
Session source field lastAttributionSource.sessionSource No
UTM parameters attributionSource.utmCampaign, utmSource, etc. No (but unpopulated unless UTMs are set up)
Aggregate reporting API /reporting/attribution Yes — not available

🔍 What We Discovered

1. UTM Fields Are Not in Use

Across all sampled contacts, utmCampaign, utmSource, and utmMedium are all null. External links (social posts, emails, partner referrals) are not currently tagged with UTM parameters, so no campaign-level breakdown is possible yet.

2. lastAttributionSource.sessionSource Is Populated

The most reliable attribution field is lastAttributionSource.sessionSource. GHL writes values like:

Session Source ValueWhat It Means
Direct trafficContact clicked a GHL SMS/workflow link (not true direct)
Organic SearchArrived at utahreia.org via Google
Client PortalSelf-registered through the membership portal
CRM UI / ManualAdded directly by a team member
Other / Phone APIInbound call or SMS auto-created the contact

3. ~50% of Contacts Lack Attribution

Contacts added via inbound call, manual import, or without a tracked web session have no attribution data. This is expected — GHL only captures session data when a contact interacts with a tracked web page or form.

Note on "Direct traffic": GHL-internal SMS workflow links do not carry UTM parameters, so clicks on those links register as Direct traffic rather than as a campaign source. This inflates the Direct count.

🔧 What We Built

A new tool — ghl_get_attribution_report — was added to api/mcp.js. It uses the same bulk-contact-fetch pattern already in the server (50 pages × 100 contacts = up to 5,000 contacts) and aggregates attribution data client-side, requiring no additional API scopes.

Tool Definition

{
  name: "ghl_get_attribution_report",
  groupBy options: [
    "sessionSource",  // recommended — reads lastAttributionSource.sessionSource
    "tag",            // aggregates by contact tags (reliable proxy for source)
    "leadSource",     // reads any custom field named "Lead Source"
    "referrer",       // referring hostname from lastAttributionSource.referrer
    "campaign"        // UTM campaign (sparse unless UTMs are configured)
  ]
}

How It Works

01

Fetch All Contacts

Fires 50 parallel API calls to /contacts/search, pulling up to 5,000 contacts across all pages.

02

Extract Attribution Field

Reads lastAttributionSource.sessionSource per contact, falling back to medium and source fields.

03

Aggregate & Count

Groups contacts by their source value and counts each group, tallying untracked contacts separately.

04

Return Sorted Report

Returns breakdown sorted by volume, plus total contact count and a note explaining known data quirks.

  "groupBy": "sessionSource",

🔄 How the Tool Evolved

The tool went through three iterations based on live testing against real contact data:

  1. Version 1 — UTM-based aggregation: Initially built to read attributionSource.utmSource, utmMedium, and utmCampaign. Testing revealed all UTM fields are null across the database.
  2. Version 2 — Tag-based fallback: Pivoted to using contact tags as a source proxy (e.g. mtg attended, community member, true wealth jv member). This worked but mixed source intent with lifecycle stage.
  3. Version 3 — sessionSource (final): Live contact inspection revealed lastAttributionSource.sessionSource as the correct, populated field. Tool updated to read this as the primary dimension, with tag and custom field modes retained as alternatives.

⚠️ Current Limitations

LimitationImpactFix
No UTM parameters on external links Cannot distinguish Facebook, email, or partner traffic Add ?utm_source=facebook&utm_medium=social to all external links
GHL SMS links register as Direct Direct traffic count is inflated GHL limitation — no current workaround; tag contacts via workflow instead
~50% of contacts untracked Source breakdown is partial Ensure all entry points (calls, imports) tag contacts with a source tag via workflow
No reporting.readonly scope Cannot access GHL's native aggregate reporting API Request scope from GHL, or use the GHL Reporting dashboard directly

🚀 Recommended Next Steps

  1. Deploy to Vercel — push the updated api/mcp.js to make ghl_get_attribution_report available to Claude.
  2. Set up UTM tagging — add UTM parameters to all external links (social posts, email blasts, partner referrals) so future contacts carry campaign attribution.
  3. Add source-tagging workflows — create GHL workflows that automatically tag contacts with their entry channel (e.g. inbound call → tag source: phone) to fill the ~50% untracked gap.
  4. Request reporting scope — adding reporting.readonly to the API key would unlock GHL's native aggregate reporting endpoints for richer data.
The tool is production-ready as-is. Running ghl_get_attribution_report with groupBy: "sessionSource" will give a real breakdown across your full contact database immediately after deployment.
